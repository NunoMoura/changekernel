# Contribute Verification

A contributor can write a focused Check as JavaScript, or TypeScript compiled ahead of execution, using declared inputs, computation and optional host-mediated structured model inference. The output is one Boolean answer with actionable natural-language feedback and Evidence references. Code and model operations are not separate Check types. Callers consume the Boolean without discarding its retained supporting record. Authors prefer small functions and use ordinary language composition only when needed; no separate composition framework is required. A Pack distributes reusable pinned definitions; first-party offerings have no privileged engine.

Adopted Wiki policy determines which conditions and exact evaluators govern a project. Installing a Pack, naming an axis or proposing a policy change does not activate it or authorize tools. Agents collect information and prepare cases; Checks are read-only and cannot repair artifacts, Wiki or Project Server state. Missing required input means unready rather than inapplicable.

Applicable adopted definitions expose input requirements before execution so agents can bind exact Wiki passages, artifacts and retained observations or report missing material. Inputs do not require a universal Wiki parameter schema. The backend can reuse a complete retained result when all declared supplied inputs, relevant evaluator/settings and validity conditions still match. Git makes retained source comparison cheap, but unchanged supporting citations alone do not establish eligibility.

Authors can test deterministic paths, recorded model interactions, genuine model assessment quality, failure feedback and input-sensitive reuse. Source identity and receipt validation do not prove interpretation or containment. Narrow input and execution bounds support local/private models without promising that every semantic question is cheap. See the [Check contract](../../../system/components/checks.md).
