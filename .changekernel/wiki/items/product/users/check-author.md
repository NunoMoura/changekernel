# Verification Contributor

A verification contributor authors or improves reusable Checks, Evidence collection methods and tests for any project domain. A Check is a read-only function with defined inputs, one passing condition, a Boolean result and actionable feedback. It can compute and request bounded model inference through the same [Check library](../../system/components/checks.md#check-library-and-execution). TypeScript/JavaScript comes first; Python is later support, not required to use a private model service.

Wiki owns adopted policy; Packs distribute evaluators. First-party and company-authored Packs use identical contracts. Contributors do not duplicate governing rules in Skills, automatically activate example policies through installation, or let a Proposed Change choose its own weaker judge. A machine-defined rule may be explicitly adopted by exact reference rather than copied into competing prose.

Authors declare input selection, activation, implementation identity, execution limits and cache dependencies, and test useful passes, contradictions, missing support and operational inability. The host, not the library alone, enforces containment. A Pack label or model confidence does not establish quality or grant permission. Preserve exact sources, conditions, limitations and feedback that identifies what could resolve a failure without silently weakening intent.
