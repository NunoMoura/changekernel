# Qualification and Benchmarks

Qualification evaluates declared subject scope and execution configuration on exact immutable candidate bytes, including both release-owned backend validation and adopted domain Checks. Native tests, structural checks, replay and injected runners supply bounded engineering evidence, not proof of operational semantic quality, custody or continuation.

The first local dogfood qualification is the bounded loop in the [release contract](package.md#minimum-local-dogfood), not completion of every benchmark scenario. Broader product evaluation should exercise software and non-software Changes, consequential contradiction/uncertainty followed by inquiry or repair, shared Planning obligations, conflicting parallel work and fresh-context recovery. Test original reasons still holding, one failed assumption with independent support, and a rejected alternative becoming appropriate.

The core loop and historical retrieval must work with zero external data connectors. Exercise promotion, retirement and re-adoption boundaries: reading an old rule, moving a file, generating a RAG answer or evicting context cannot silently change authority. Missing historical objects, private inputs and unavailable evidence must remain honest limitations.

Compare quality and effort with a well-written prose/Git baseline. Measure consequential omissions, false acceptance, unnecessary rejection, repeated inquiry/effects, context loss, resource use and human intervention. More metadata, sources or retrieved text is not inherently better. For delegation experiments, count the main session and all workers, handoffs, review, repair and validation; compare total cost, elapsed time and accepted quality with direct work. A lower worker token price or a completed subagent run is not evidence of savings.

Qualify the actual backend validators and domain Check definitions, model/runtime and bounded inputs, including private/local execution without remote fallback. Measure first actionable feedback, total tokens/cost/time through repair rounds, false activation, cache reuse/invalidation and fresh-session reconstruction. Include denied extension writes, network and credential access, exhausted budgets, missing inputs, source instruction attacks and unchanged retries that must not become a pass lottery. A smaller model or Pack signature is not semantic qualification.

## Stage and ownership challenge matrix

| Boundary | Required challenges |
| --- | --- |
| Common backend contract | Use software and non-software cases with the same lifecycle rules. Block missing common validation even when every adopted domain Check passes; reject attempts to waive it through Pack configuration or caller-declared ownership. |
| Domain policy | Keep domain methods and thresholds out of universal rules. A backend pass cannot replace a failed or missing required engineering, scientific or other domain assessment. No domain Check selection must not imply domain assurance. |
| Decision | Unclear intent, omitted effects, unsupported premises, counterevidence, legitimate commitment revision and persuasive but unjustified pursuit. |
| Planning | Accepted purpose with a non-covering plan, missing prerequisites, conflicting intermediate obligations or domain-inadequate methods. Decision acceptance is not a Planning pass. |
| Implementation | Authorized work with defective contributions, concealed deviations, mismatched execution observations or unsupported partial-completion claims. Domain Checks inspect authorized collected observations rather than performing repairs. |
| Review | Individually passing work whose combined result fails, overstated realization, missing domain support or unresolved required outcomes hidden as follow-up work. |
| Retention and transition | Changed ownership, stage question, implementation, policy, input membership, authority or external freshness invalidates inappropriate reuse. Preserve valid false results; never relabel a previous stage's verdict or silently repeat an uncertain attempt. |

Use independently reviewed good, bad, ambiguous and adversarial examples for each common condition and each adopted domain question. A backend catalogue or a correctly shaped response is not qualification. The first narrow dogfood run exercises its actual supported case; broader domain claims require broader qualification rather than fictional coverage.

Freeze corpus, environment, supported capabilities, resource/time/output and token/cost/retry limits and quality thresholds before testing. Binding failures cannot be averaged away. Use the [immutable release boundary](package.md); real-world outcomes need observations beyond committed documents.
