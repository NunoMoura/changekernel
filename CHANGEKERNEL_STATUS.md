## Rust runtime research — source-backed shortlist, not adoption

The user wants deeper Rust ecosystem research so ChangeKernel can implement its existing ideas natively and efficiently, potentially adapting an existing runtime rather than rebuilding everything. The desired combination remains Pi-style context/tools/streaming, Jaz-style programmable reasoning, and Hermes/OpenClaw-style durable coordination and delivery ownership. The earlier findings and operating-model proposal are preserved at `d9b59946556c9afae3220cd4b0849daf2491b8e0:CHANGEKERNEL_STATUS.md`; the restart-witness investigation remains at `22e5a93ec8edaca56c2ffc5083e263b4e35ac276:CHANGEKERNEL_STATUS.md`. This research changes the implementation shortlist, not the Workspace/State/Change model, safety requirements or current implementation gates.

**Recommendation:** pursue selective Rust component reuse before a from-scratch inner loop or a whole-CLI fork. Evaluate two bounded candidates: **KISS's portable loop** for Pi/Jaz fit and **Rig's host-driven `AgentRun`** for explicit execution control. Keep `pie` as the next Pi-shaped alternative and `genai` as a provider-only option if neither loop fits. Do not stack multiple agent loops or import every product's scheduler, storage and UI. No dependency, fork, API/schema, runtime replacement or deployment is adopted by this note.

### Consequential code observations

1. **KISS offers real reusable boundaries, not only a fast terminal.** Its [agent crate manifest](https://github.com/racetozero/kiss/blob/53d545de178c6e3e7d51a7232a03e2ae9116a173/crates/kiss-agent/Cargo.toml) separates portable loop/contracts from native tools. `AgentLoopConfig` exposes injected streaming and context/turn hooks; `AgentTool::execute` receives cancellation and streamed-update plumbing. `SessionManager::build_session_context` reconstructs active branch model/thinking settings and compaction/branch summaries. Prefer that bounded core over importing ambient credential/config/skill discovery and every SDK/TUI capability.
2. **KISS is unusually relevant to Jaz-style execution, but its replay key is insufficient for us.** `kiss-workflow` is a Rust-written restricted JS-like interpreter with named `args`, `agent`, `parallel`, `pipeline`, structured results and bounded steps/fanout. It is not Node or Python, and it is not full Jaz compatibility. In [the runner/cache contract](https://github.com/racetozero/kiss/blob/53d545de178c6e3e7d51a7232a03e2ae9116a173/crates/kiss-workflow/src/runner.rs) and `interp/builtins.rs::builtin_agent`, a completed result is reused by call position and prompt before the new model, effort, schema or timeout is built into an `AgentRequest`. Changed source/tool/Kernel/authority is not established by that cache key. The CLI's saved workflow source/args/cwd are useful context, not a proof that cached dependent work remains eligible. Explicit restart resets the local retry counter; agent failures may become `null`. `Limits::sanitized` raises a supplied step cap below 1,000 to 1,000 and a zero agent cap to one; those limits cannot stand in for an independently stricter parent allowance. Do not adopt these as mandatory Check, durable aggregate-budget or unknown-effect policies.
3. **KISS persistence is stronger than a bare append, but still a transcript facility.** `SessionManager::append_lines` flushes and calls `sync_data`; `open` warns and skips malformed entries and repairs a missing newline when entries otherwise parse. Workflow summaries use temporary-file rename without an inspected sync barrier. These paths do not establish the protected accepted-prefix, persistent incident memory, ancestry protection or current-authorized replay required by ChangeKernel. A restricted interpreter and cancellation token likewise do not prove outer containment or process/provider quiescence.
4. **Rig has a useful explicit dispatch boundary in a released source tag.** [Release stepper](https://github.com/0xPlaygrounds/rig/blob/d5a34986a1ad57f1e9c5984b82f8d7438ffc717e/crates/rig-agent/src/agent/run/mod.rs) declares serializable run state without live model/tool/hook objects. Current `next_step` returns model/tool work and preserves pending tool calls for resumed drivers. The inspected release test serializes a run with pending tools and supplies approval/denial results after reconstruction; it was read, not executed. This is an attractive place for ChangeKernel to own admission and dispatch. Re-emitting a pending call is not proof that an earlier external effect did not happen. Rig's [current restoration contract](https://github.com/0xPlaygrounds/rig/blob/0887455e2a312fe08e5dc2fb3d9c046ddc515f14/crates/rig-ecs/CONTRACT.md) explicitly leaves unanswered-write deduplication/reconciliation with the host and distinguishes saved descriptors from actual endpoint/credential authority. Those limits must remain intact.
5. **`pie` has useful session seams, not a ready authority store.** [JSONL storage](https://github.com/c4pt0r/pie/blob/b72579680bdfe616edbc05808fb1395a1be3660f/crates/agent/src/harness/session/jsonl_storage.rs) skips malformed entry lines, appends without an explicit sync barrier and uses a separate leaf sidecar. Source tests cover ordinary reopening, branch selection and compaction; they do not qualify power-loss recovery. `CostTracker` sums completed assistant usage in memory and explicitly leaves caps to later work. `run_one` bounds shutdown of its update-pump task, but queues updates through an unbounded channel. These are concrete adaptation costs for long-lived bounded workers.
6. **PiCrust's strongest durability wording exceeds the inspected mechanism.** [Session storage](https://github.com/CratorAI/picrust/blob/e0f63575a6e774c22d477f63937c05929e310112/src/session/storage.rs) appends through `BufWriter` without explicit flush/sync, writes metadata directly with `File::create`, and exposes `save_messages` that truncates/rewrites history. Loading parses each line and errors on malformed JSON. This does not justify “survives power failures ... without corrupting state.” Its `spawn_with_local_rules` places handles in an in-memory map and starts Tokio tasks; that is concurrent execution, not a reboot-surviving queue or OS privilege boundary.
7. **NCA's supervisor terminology must not be mistaken for qualified recovery.** [SessionStore](https://github.com/madebyaris/native-cli-ai/blob/2268932edeaf4b18c8c8e9548411723bbe1328fb/crates/runtime/src/session_store.rs) writes a temporary JSON snapshot then renames it without an explicit sync barrier. `cleanup_stale_sessions` checks PID liveness/socket existence and marks apparently abandoned running sessions as `Error`; it does not reconcile effects. Worktrees and permission prompts do not protect custody from same-UID workers. Useful detached-session/IPC ideas remain, but this is a different contract.
8. **Check actual licenses and dependency subjects.** [`pi_agent_rust` LICENSE](https://github.com/Dicklesworthstone/pi_agent_rust/blob/6e75f6b6bdc4cc958a8829c4d85461818af201d8/LICENSE) is the early exclusion, irrespective of advertised performance. KISS/pie/Rig/nktkt have MIT text; genai's manifest and license files provide the stated alternatives. PiCrust/NCA documentation indicates MIT but does not settle the missing-notice detail. No legal enforceability opinion or transitive-license audit was performed.

These findings compare consequential boundaries, not test counts or feature-list length. Missing our guarantees is not automatically an upstream defect: the projects generally target different trust, persistence and operating contracts.

### Proposed composition and focused comparison

An all-Rust implementation is plausible without taking another product's governance model. Literal Jaz is Python; adopting its ideas in a Rust-written strategy executor is different from embedding Jaz unchanged or claiming drop-in Jaz compatibility.

- **ChangeKernel owns:** Workspace/Change/Work identity; exact Kernel and runtime bindings; authorized typed operations; native rights; acceptance/reentry; current eligibility; aggregate consumable budgets and reusable capacity; effect uncertainty; result retention/delivery; mandatory assessments and controller handoff.
- **Reusable execution components may supply:** normalized provider streaming, tool-call plumbing, bounded context projections, session-tree/compaction mechanics, a no-I/O run stepper or a portable loop, and a restricted programmable strategy layer.
- **Keep distinct:** runtime transcript/cache versus authoritative Change Trace log/checkpoint; completion versus delivery; cancellation versus proven quiescence; deterministic replay versus permission to repeat effects. A simple model loop does not eliminate necessary operational state or Work dependencies.

Candidate A is a narrowly configured KISS portable loop plus selected provider/context facilities and a host-adapted strategy interface. Candidate B is Rig's stepper driven by ChangeKernel-owned admission/dispatch plus selected provider facilities and an explicit strategy layer. Do not assume importing KISS's whole SDK is equivalent to its portable crate, or that using Rig requires Bevy/ECS. Do not combine both agent loops by default. `genai` is a fallback provider component for a small owned loop, not an additional mandatory abstraction layer. Historical SQLite meanings and existing TypeScript adapter semantics remain frozen until a separately accepted boundary change.

Before choosing, propose one disposable external comparison with the same captured context, fake provider/tool scripts, resource bounds and containment topology. Cover interrupted streaming and partial tool arguments; cancellation with live descendants; same prompt with changed model/schema/source; exact result lookup versus new dispatch; crash after a simulated effect but before result recording; spent/unknown budgets across restart; branch/compaction constraint preservation; bounded event queues; and no execution during history reconstruction. Fake tools must exercise observable failure boundaries, not merely return success strings. A later live quality/cost comparison needs separate authorization, matched models/information/budgets and no uncontrolled external effects.

Measure cold/warm headless readiness, loaded-context and peak RSS/PSS, many-worker density under equivalent isolation, streaming/backpressure overhead, cancellation/settlement latency, packaging/build dependencies and maintenance changes needed. Compare against the exact retained Pi adapter subject for integration claims; use installed Pi 0.87.1 only for explicitly versioned terminal comparisons. Do not compare a bare Rust loop to Pi with unrelated extensions/LSPs enabled. Large efficiency gains remain a hypothesis until this comparison, and task success/correctness must survive any optimization. No prototype/build/dependency installation is released by this research note.
