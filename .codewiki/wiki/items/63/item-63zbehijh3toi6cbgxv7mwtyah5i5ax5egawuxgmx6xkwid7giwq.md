# Automate Safe Work

As a maintainer, I want a standalone CodeWiki to advance compatible work so routine progress survives browser, terminal, Run Process, or channel disconnection while unsafe progression remains blocked or explicitly stopped.

## Acceptance signals

- CodeWiki owns durable Project Server, Runtime, Checks, WorkState, Workbench, and recovery responsibilities and starts exact pinned DSH Run Processes through neutral Run Ports.
- Project Server reconnects Clients to durable Project Server operations and canonical WorkState rather than private conversation state.
- Decision admits no unresolved semantic contradiction against the exact accepted active Changes, and expected-head CAS closes concurrent admission races.
- Planning appends one immutable Change-scoped Work Graph delta instead of regenerating one whole-project plan; Project Server alone derives readiness, Claims, Assignments, and placement.
- Project Server creates exact Stage Producer attempts, selects and Claims ready Work Units, isolates Workbenches, starts DSH-backed or Delegated Runs, applies the same stage-wide Implementation Check Pack policy to every Work Unit Candidate, integrates passing output into private Change lineages, verifies admitted CodeWiki Plugin Receipts, and advances only after all required units complete.
- Runs bind exact prompts, Skills, tools, routes, Work Continuity, Run Context Bundle or Gate Evaluation Package inputs, queries, budgets, compaction checkpoints, outputs, and raw session evidence. Delegated and External Agent Client receipts claim only facts CodeWiki actually controls or observes.
- Project Server reacts to admitted intent, Candidates, Gate outcomes, confirmations, scheduled reconciliation, and repository divergence; commits alone never imply stage progression.
- Backend v1 persistent producer DSH Agent Sessions may span bounded Runs under exclusive leases and exact-head CAS. The Semantic Kernel target closes each physical Session at its terminal producer Run Receipt, starts subsequent Work Continuity Run in a fresh Session from exact canonical rehydration and predecessor evidence, and permits same-Session resume only for recovery of the same in-flight Run.
- Canonical/proposal Git commits, fixed-path Wiki/Trace bytes, Candidate, Gate feedback, requirements, Evidence, Results, and Receipts survive every rollover. Fresh Runs rebuild WorkState and materialize a new authorized Run Context Bundle; prior bundles remain execution Evidence only. DSH compaction stays intra-Run and non-authoritative.
- Review judges one exact aggregate Change lineage for complete acceptance and cross-Work-Unit integration; it may be fully automated with independent Model and Code Checks, while human Evidence remains optional unless project Checks require it.
- Every accepted Change reaches exact completion or retains explicit unresolved requirements without requiring surveillance of incidental or inaccessible child-harness activity.
- Missing capability, stale state, external divergence, incomplete Evidence, Run Process failure, or absent authority never silently relaxes policy or crashes the CodeWiki.
