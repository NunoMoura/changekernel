# Provider Boundary

Provider Boundary covers AI providers, Git/Delivery services, delegated Agent products, package registries, external workspaces, and collaboration platforms. Providers own networking, provider-native authentication/state, credentials, billing, and availability. CodeWiki owns user-authorized route/capability policy, exact Run or Plugin request binding, receipt validation, custody classification, expected-head policy, and semantic interpretation.

Provider identity never grants Actor, stage, Change, Check, Gate, Result, Git-ref, completion, or effect authority. A successful response proves only the bounded fact authenticated by its receipt. Unknown, partial, stale, contradictory, rate-limited, or unavailable provider state remains explicit.

Agent routes are role-specific: Decision, Planning, Worker pool, Review, and Model Checks. No generic fallback silently changes provider/model. Project Server chooses a Worker route only from current authorized offers; DSH owns actual model/provider execution mechanics. Route changes occur between DSH Runs with fresh authorization and exact context. Proposal or Work bytes cannot choose their evaluator.

AI Gateway normalizes supported DSH-owned AI/model-provider mechanics while preserving provider/account/credential-reference/model/options identity, usage, cancellation, transport reconciliation, and authenticated receipt. Provider transport recovery remains inside one authorized Run/idempotency identity and cannot create another semantic execution. Credentials remain owner-private outside project Git and model-visible context. Ambient credentials, secret-bearing project config, unsupported auth/protocol, and custody CodeWiki cannot prove fail closed.

CodeWiki Plugins mediate Git, source, remote, verification, workspace, and Delivery mechanics through immutable capability-scoped Request/Receipt contracts. Project files may select admitted identities/config but cannot install executable code, name local executable paths, widen permissions, or grant canonical writes. Remote observation may open Change Intake; remote publication remains a post-completion protected effect.

External Agent Clients use authenticated Kernel API and disclose custody gaps. Delegated execution is accepted only when explicit route policy and receipt contracts prove required inputs, outputs, tool/effect custody, and cancellation. Brand or claimed compatibility is insufficient.

DSH package protocols remain DSH-owned mechanics bound by the exact Agent Runtime/DSH qualification closure. Public semantics use DSH Run and CodeWiki Plugin ownership without duplicating provider mechanics. Unsupported obsolete provider envelopes remain in release evidence rather than active Product readers or inferred adapters.
