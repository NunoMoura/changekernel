# Preview

Preview is a separately authorized effect behind the host-neutral Preview port. A Preview adapter starts bounded local targets and captures browser, page, interaction, recording, or log observations without acquiring project or lifecycle authority. Product or tracked Project configuration defines admitted Preview profiles; an Agent or Check selects only an authorized profile and cannot supply an arbitrary launch command.

`preview.work` is an optional capability granted to one exact Worker Run, Assignment, and isolated worktree. Its revocable handle binds the Preview profile, current worktree generation or captured tree, route/environment identity, loopback and network policy, process/resource/output bounds, and lease/TTL. The Worker may start, observe, and stop the target repeatedly within that authorization. These observations are producer feedback: they may inform implementation and appear in the bounded Run receipt, but they are not independent Evidence, Check Results, or Gate authority.

`preview.verify` is an independent Check capability for one immutable Gate subject commit/tree. Check Runner invokes it without producer Session memory, receives an exact observation and closure receipt, and returns the untrusted receipt to Project Server. Only after subject, profile, environment, custody, bounds, and process-tree quiescence validate may the observation be admitted as Evidence for an active Check to judge. Preview itself never passes a Check.

Every handle is scoped, unforgeable, short-lived, and idempotency-bound. Project Server authorizes use and requests cancellation; Preview adapter and qualified Execution Host physically enforce containment and cleanup. A `preview.work` handle may follow generations only inside its unchanged authorized Assignment/worktree; every request and observation captures the exact current generation and no observation survives generation drift. A changed Assignment, worktree identity, profile, route, environment, or authority requires a fresh handle. A `preview.verify` subject is immutable and any subject change requires fresh authorization. Timeout, lease expiry, cancellation request, process exit, missing closure, or unavailable Preview yields an explicit operational stop until terminal receipt or independently proven quiescence; it never fabricates semantic failure or permits duplicate execution.

Preview cannot mutate Wiki, Trace, managed refs, lifecycle state, provider state, or canonical project bytes; publish a product; grant credentials; or turn producer observations into verification Evidence. Screenshots, recordings, pages, logs, sockets, and temporary processes remain outside canonical semantic authority unless an explicit retention policy admits exact material. A remote, shareable, or long-lived Preview is a protected external effect implemented only through an admitted Plugin behind the same bounded capability semantics.
