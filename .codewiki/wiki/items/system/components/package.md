# Product Package and Release Boundary

The package supplies CodeWiki's semantic service, bounded interfaces, and explicitly supported integrations. Git owns storage/history; Wiki and Change own consolidated knowledge and intentional evolution; the kernel owns semantic distinctions and transition consequences. Packaging must not turn one client, model provider, Git host, or software workflow into the product's ontology.

Public interfaces expose supported semantic operations, not raw kernel internals, credentials, writers, private custody or adapter handles. Capability reporting reflects actual qualified support. No mandatory project Skills or Check Pack installation duplicates Wiki procedures or obligations. Versioned data/transport contracts remain precise without imposing proprietary envelopes on ordinary Markdown authorship.

An immutable release identifies its exact source, dependency/package closure, semantic contract and supported execution profile. A policy digest alone does not identify all executable bytes. Qualification and activation evidence apply only to their named subjects and scope; package version labels and old test counts do not transfer assurance to modified code.

Candidate development uses ordinary native edits, diagnostics and tests under its approved scope. Pack and exercise candidate bytes in disposable external projects with isolated settings, never as a controller loaded from its own mutable checkout. Generated views, private runtime state, credentials, caches, sockets and release artifacts do not belong in Project Git.

Existing-state conversion is a separate protected transition with exact mapping, backup, collision rejection, recovery and applicable authority. Do not dual-read/write incompatible roots, invent historical Changes, or infer migration support from a new reader. Prepare replacement guidance before freezing the exact handoff candidate; any post-freeze correction requires a new commit, unique version, and qualification.

An immutable release must pass exact-subject qualification and explicit activation before dogfood use. Activation alone does not transfer controller authority; required handoff is explicit. Candidate N+1 never governs itself. Higher-priority truth, safety, and source-checkout restrictions do not expire with temporary bootstrap procedure.
