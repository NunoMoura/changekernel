# Package

`@nunomoura/codewiki` is one passive Product package containing the Semantic Kernel, Project Server, curated Product UAPI historically named Kernel API, Client and Check SDKs, schemas, selected Git/Check/DSH/Preview adapters, and release-managed Check Pack templates. Installation performs no lifecycle hook, project write, Agent/Check/Preview/Plugin execution, credential lookup, daemon start, migration, provider call, or telemetry. Publication is a separately authorized Delivery and does not change passive installation behavior.

The Product contains no Pi wrapper, source-checkout controller, or independently evolving development authority. Native Pi and Git remain external bootstrap and recovery paths. When CodeWiki develops itself, an immutable externally installed Product N is semantic controller for exact candidate N+1; mutable candidate code never enters Product N's module graph or qualification authority.

Public surfaces are version-neutral semantic Product/Client APIs plus explicit versioned envelopes and narrowly curated package entrypoints. Kernel API is served by Project Server and never exposes direct pure-Kernel modules, stores, ports, adapters, or authority. Internal TypeScript modules are private by default. DSH owns Agent runtime mechanics. An Agent-capable Product release may bundle or pin one exact qualified DSH adapter/package/Execution Host closure without relabeling those mechanics as CodeWiki semantic authority.

Check Pack resources are inert files. First bootstrap or explicit adoption may validate/copy exact templates and record source/tree identity in `.codewiki/check-packs.lock.json`. Installed project Packs are immediately editable/removable and never silently restored. Project-specific controller Packs do not become shipped defaults.

Executable CodeWiki Plugins are installed and admitted outside project files with exact manifest, implementation/dependency digests, protocol range, permissions, isolation, capabilities, configuration schema, and qualification Evidence. `.codewiki/**` may select only an admitted identity/config and cannot name executable paths or install code. DSH Plugins remain in DSH-owned plane.

Private state lives below an external repository-identity-bound State Root. Package files and project Git never contain credentials, DSH Sessions, sockets, leases, raw logs, caches, generated Views, worktrees, or provider state. Uninstall preserves project and private state by default; destructive cleanup requires explicit verified backup and authority.

Every released package binds exact source commit/tree, archive SHA-256/npm identity, package file list, lockfile/dependency closure, Product Build identity, pure Kernel Build identity, support matrix, protocol/schema closure, exact DSH and Preview closure where applicable, Check Pack resources, Product-fixed role/check policy bytes, qualification evidence, and controlling Product identity. One package name and semantic version identifies exactly one archive digest and is never rebuilt with different bytes; corrected prereleases receive a new version. Kernel Build identifies deterministic semantic interpretation only; Product Build additionally binds Project Server, public API, adapters, packaged policy, and dependency closure. Packed bytes are installed and tested in disposable external projects. Source-checkout development machinery, benchmarks, private state, and credentials do not ship.

Released Product N governs exact committed release candidate N+1 using accepted protected-head policy. Ordinary engineering checkpoints are immutable Git/CI evidence, not release lifecycle subjects. Any post-freeze release-candidate correction creates another commit, uniquely versioned package, and exact-subject qualification. One explicit human decision authorizes activation of the qualified identity. Release activation pins immutable verified package bytes outside the governed checkout and remains independently recoverable through Pi-native and Git paths; it does not automatically promote those bytes to semantic controller.

Controller promotion is a separate protected handoff. The current controller must quiesce, complete a verified backup, qualify the exact target Product and converted state, obtain authenticated human authority, and atomically transfer expected state before retiring. Source and target controllers never overlap, and the target has no normal startup path that infers unsupported predecessor state.

A release advertises only predecessor formats and host/runtime combinations it has explicitly requalified. When a predecessor converter exists, it is exact, one-shot, backup-first, and separate from normal startup. Unknown or unsupported pre-stable state fails closed; Git history, immutable release artifacts, and qualification evidence preserve obsolete implementation without shipping active readers.
