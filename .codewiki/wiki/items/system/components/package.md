# Product Package and Release Boundary

The package supplies the semantic service over native Git-backed Wiki and Change. Git/history are foundational; external data connectors, hosting/editor integrations and supported execution profiles are separate concerns. Optional connectors must not become prerequisites for native knowledge or history. Public interfaces expose semantic operations, not private writers, credentials or custody.

An immutable release binds exact source and dependency/package closure, semantic contracts and supported profile. A policy digest or version label alone does not identify all executable bytes or transfer qualification. [Benchmarks](benchmarks.md) define outcome and evidence expectations.

Develop with native edits, diagnostics and tests under approved scope. Pack/test candidates only in disposable external projects with isolated settings, never as governors loaded from their own mutable checkout. Private runtime state, generated views, credentials, caches, sockets and package artifacts are not Project source truth.

Existing-state conversion is separately authorized and needs exact mapping, backup, collision rejection and recovery. A new reader does not grant migration support; do not dual-read/write or invent historical acceptance.

Prepare replacement guidance before freezing a uniquely versioned candidate. Corrections after freeze require new bytes/version and qualification. Dogfood requires exact-subject qualification and explicit activation; activation alone does not transfer controller authority. Required handoff is explicit and quiescent. Candidate N+1 never governs itself; truth/safety/source-checkout restrictions do not expire with bootstrap procedure.
