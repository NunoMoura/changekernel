# WorkState

WorkState is a deterministic disposable projection over exact Git Project snapshots, managed Change refs and Traces, stage Gates and Results, durable Work facts, Evidence, configuration, and protected-effect receipts. It supports queries, scheduling, guards, and recovery without becoming another canonical database or lifecycle owner.

For each Change, WorkState derives proposal tip, state, Change type, realization route, Change/Completion commits, current phase, blockers, active Gate and Checks, contributor/Actor refs, committed Wiki target, planning facts, Work Units/dependencies, Claims/Assignments, integrated Git ancestry, Review status, completion, and external effects. It distinguishes proposed, deferred, rejected, withdrawn, committed, blocked, superseded, and completed outcomes from append-only Trace rather than mutable status rows.

Accepted planning operations in Change Traces define Work Units and edges. WorkState derives the global Work View, readiness, conflicts, and current unit statuses; no separately writable canonical Work Graph exists. Passing work integrates onto Change refs, so Git ancestry plus Trace supplies integration facts; no peer private lineage or aggregate store is authority.

Each stage View selects one exact Project commit or Change tip. Decision shows alternatives, contributors, type-conditioned active Checks, proposed Wiki writes, receipted reads/dependencies, and active-Change compatibility. Planning shows committed target and proposed Work Units. Implementation shows Work Unit result commits, Gates, dependencies, and integration. Review shows exact integrated Change tip against Committed Change.

Project Server rebuilds WorkState before scheduling, Gate creation, integration, completion, recovery, and bounded Client/Agent queries. Every consumer binds the exact source identities and projection digest. Stale WorkState cannot authorize a Git ref move, Check selection, Claim, integration, Change Commit, Completion Commit, or protected effect.

Private live capacity, leases, process state, DSH internals, caches, and raw evidence remain with their operational owners. WorkState may project them through verified bounded records but never converts absence, process exit, or model output into semantic authority.
