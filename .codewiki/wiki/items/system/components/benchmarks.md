# Benchmarks

Repository-root Benchmarks test whether CodeWiki's added ceremony materially improves safe accountable work. They compare the same supported Agent/model route, task, Project snapshot, tools, network, budget, timeout, concurrency, retries, environment, and trial order in paired `alone` and `codewiki` modes. Benchmark code and fixtures do not ship in the production package.

External fixtures and deterministic or human-approved oracles establish task truth. Measurements include task success, committed-intent coverage, false Gate passes/failures, stopped work, Wiki/Trace provenance, feedback-guided repair, stale-head violations, interventions, recovery, time, token use, latency, and cost. Missing telemetry remains unknown and cannot be scored as zero.

Wiki proposal benchmarks compare full Item rewriting, Git diff, byte splice, and structural Item editing over additions, edits, moves, retirements, relationships, and no-Wiki-diff repair Changes. Exact resulting commits/trees/blobs and encoded/repeated/new bytes are measured without granting admission or policy authority.

Context benchmarks compare full read-only Project mounting with deterministic target-Item selection plus bounded exact Wiki/Project queries. Exact answers must match while unrelated visible bytes, materialized files, query volume, and token use remain measured. A strategy that saves context but loses required facts, stable identity, authorization, or source receipts fails.

Code Mode benchmarks compare direct tools, batch queries, and separately contained model-authored programs. Selection remains workload-specific. Programmatic composition is eligible only when measured traffic falls without crossing task-quality, authority, or containment floors. Worker threads and ordinary child processes are benchmark evidence only, never production security boundaries.

DSH Run-boundary benchmarks compare longer DSH-internal continuity with fresh semantic Runs that rebind exact Git/Wiki/Trace facts and permit compaction only inside DSH-owned execution. Deterministic replay, CAS, recovery, provenance, and authority fixtures require 100% pass and zero protected-effect or stale-head violations. Model-quality cells use enough paired trials and pre-frozen estimators to report uncertainty rather than a single trust score.

An execution strategy qualifies only when task-success lower bounds remain within approved non-inferiority margins against the currently activated strategy, authority-critical fact loss remains zero, repair loops do not regress, and either token/context reduction or an explicitly authorized quality gain justifies latency. Exact thresholds, fixtures, routes, estimator, seed, invalidation rules, and exception authority bind the qualification artifact before unblinding.

Failure keeps the last qualified execution strategy. A Benchmark cannot create or commit Changes, mutate Wiki/source, select active Checks, promote a release, schedule work, or replace project Gate policy. Operational discoveries enter ordinary Change Intake.
