# Implementation

Implementation realizes one accepted Work Unit at a time against a Committed Change. Project Server creates an isolated Git worktree/branch from the exact Change snapshot, binds one Assignment and authorized route, and starts a bounded DSH Run. Every result commit is a full Project snapshot; Work Unit and Change scope constrain its admitted delta, not its tree size.

The Worker receives exact Work Unit identity, committed Wiki target refs, current Change and project commits, dependency outputs, relevant Wiki context/tools, active feedback, writable source scope, and capability/budget bounds. `.codewiki/wiki/**`, `.codewiki/changes/**`, managed refs, authority, and lifecycle remain read-only or unavailable. A Worker that discovers wrong or missing meaning reports a gap; it cannot repair accepted Wiki while coding.

Each completed Work Unit attempt identifies one exact result commit/tree and DSH Run receipt. Project Server creates an Implementation Gate whose active Checks derive from exact Implementation Check Packs, frozen Change type, Work Unit subtype/scope, and exact subject. All Work Units share the same policy universe, while fit-for-purpose active subsets and inputs may differ. Workers, Planning, routes, and models cannot select Checks.

A failed Gate returns exact Results to that Work Unit. Operational inability stops without Result. A passed Gate qualifies only the exact result snapshot. Project Server then revalidates Change and Work Unit identity, dependencies, Assignment/worktree custody, changed paths, Gate, and expected Change tip before integrating the commit onto the managed Change ref.

Git ancestry is the integration lineage. Trace records the Work Unit, result/Gate refs, exact parent and resulting commits, custody, conflict, and admission. No private integration lineage object, duplicate aggregate store, or per-unit canonical merge is authoritative. Stale base, dependency drift, changed bytes, lost custody, or conflict blocks integration and produces another explicit attempt or reconciliation.

Implementation continues until every required Work Unit is current, passing, dependency-complete, and integrated exactly once. WorkState derives progress from Trace and Git. The exact integrated Change tip then becomes Review subject. Unit Gates prove local work only; they do not complete Change, approve cross-unit behavior, or authorize Delivery.
