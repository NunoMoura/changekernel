# Benchmarks

Repository-root Benchmarks compare the same supported Agent, model route, task, repository snapshot, tools, network, budget, timeout, concurrency, retries, environment, and trial count in paired `alone` and `codewiki` modes. Their TypeScript is checked with product source but excluded from the production build and package; no `src/benchmarks/**` production root exists.

External fixtures and oracles determine truth. Benchmarks measure task success, intent coverage, false Gate passes and failures, stopped attempts, Evidence completeness, feedback-guided revision success, interventions, recovery, time, and cost. Wiki proposal encoding benchmark `1.0.0` compares full Item-file rewriting, unified Git diff, byte splice, and structural Item editing over representative additions, edits, moves, retirements, relationships, and empty-Wiki-diff repair Changes. It reports exact proposed-Wiki commit/tree/blob and proposal-record identity, encoded/repeated/new bytes, and duration without granting policy authority. Project Context access benchmark `1.0.0` compares full read-only repository mounting with a derived metadata index plus explicitly selected bounded files; exact selected results match while unrelated mounted bytes, materialized-file count, and query duration remain measured. Current evidence selects the derived-index strategy.

Code Mode benchmark `1.0.0` compares native direct calls, native batch calls, and secure Code Mode over the same snapshot-bound workload. It records source, cached-input, model-output, and tool-result tokens; repeated- and new-byte ratios; Candidate-to-edit amplification; turns; request, result, and ledger bytes; latency; compaction; quality; and a deterministic trace digest. Selection is workload-specific rather than global: native direct remains the baseline for one small query, native batch for a fixed independent query set, and secure Code Mode is eligible only when bounded local composition reduces model/tool traffic without crossing the configured quality floor. Worker-thread execution is benchmark evidence only and never a production security fallback.

Work Continuity benchmark `1.0.0` compares four paired strategies: one long Session without compaction, Backend v1 cross-Run continuity with its exact DSH and CodeWiki Compaction Summary implementation, fresh Sessions at terminal producer boundaries without local compaction, and fresh-boundary Sessions with compaction available only inside one Run. Isolated strategy modules run inside one non-production benchmark Build; `long-compaction` must reproduce frozen Backend v1 goldens, while each strategy binds its Work Continuity and compaction-policy digest and the target freezes its intra-Run pressure thresholds. Every pair otherwise fixes provider, model, account, route, benchmark Build, prompts, tools, context window, task snapshot, authority, budget, timeout, retries, concurrency, and trial order. Workloads cover Decision revision, Planning repair, tool-heavy Implementation, typed Review feedback, stale heads, changed Assignment and lineage, crashes around tool effects, corrupt Session bytes, Build/route/authority rollover, source revocation, and the empty, software, research, legal, design, music, and logistics scenarios.

The benchmark records task success, required-fact recall, unsupported facts, stale references, feedback uptake, unresolved-Completion-Requirement retention, repair loops, interventions, recovery, source/cached/uncached/output/tool/rehydration/compaction tokens, request/first-token/Run/boundary/end-to-end latency, AI Provider cache facts where authenticated, and retained artifact bytes. Deterministic replay, CAS, recovery, provenance, and authority fixtures require 100% pass with zero protected-effect or stale-head violations. A model-quality cell is one scenario-family, workload, and route tuple with at least 30 valid paired trials. Before target outcomes are unblinded, analysis freezes trial order, strategy-policy digests, invalidation rules, estimators, equal-cell weighting, and paired-bootstrap seed and algorithm. Signed rate or quantile contrasts use target minus baseline; reductions use `(baseline - target) / baseline`; latency increase uses `(target - baseline) / baseline`. Admitted trials are intention-to-treat; timeout, stop, recovery failure, and missing required facts count against the applicable metric. Only authenticated failure before either strategy reaches a model-visible or effectful event may invalidate a retained pair. Unknown telemetry makes its qualification branch unavailable, never zero, and no route or scenario may be dropped.

`fresh-boundary-local-compaction` qualifies against `long-compaction` only when the paired-bootstrap 95% lower task-success bound is at least -3 percentage points overall and -5 for every scenario family; each overall stale-reference and required-fact-loss upper bound is at most +1 point with zero authority-critical loss; repair-loop median and p95 upper-difference bounds are at most zero and one; and either the median billed-input-token reduction lower bound is at least 15% or the p95 context-loss reduction lower bound is at least 25%. A relative branch with zero baseline denominator is unavailable. Median end-to-end-latency increase has an upper bound of at most 10% unless a pre-unblinding G10 authorization binds the candidate Build, routes, fixtures, minimum quality gain, maximum latency ceiling, approver, and Evidence and the observed quality-gain lower bound meets that minimum. Recovery must use canonical state without reading project meaning from DSH bytes.

Failure leaves Backend v1 Session Continuity active and returns the hypothesis to architecture review. Every result binds complete fixture, route, Build, strategy-policy, code, trial, invalidation, raw-measurement, estimator, weighting, bootstrap, exception, and analysis digests; a Benchmark cannot promote the migration itself.

Operational discovery uses Discovery Findings or explicit Improvement Assessments instead. Benchmarks cannot generate canonical Candidates, mutate product source, select Changes, schedule Stage Loops, promote releases, or duplicate project Check Packs and Gate policy.
