# Provider Boundary

Provider Boundary represents project hosts, Delivery services, AI Providers, delegated Agent products, package registries, and collaboration platforms. Providers own networking, authentication semantics, credentials, billing, and provider-native state. CodeWiki owns user-authorized route policy, exact Run binding, receipt validation, freshness, expected-head policy, custody classification, and interpretation. Provider identity never grants Stage, Candidate, Check, Gate, transition, or effect authority.

The user authorizes one exact Harness route, inherited or overridden Decision, Planning, and Review producer routes, an independent Worker route pool, explicit Worker escalation transitions, exclusions, and budgets. Model Check routes remain separately owned by Check definitions and never inherit Harness or Worker policy. Project Server selects a Work Unit route only from the authorized Worker pool, records one Work Unit Model Assignment, and binds one exact provider, account, credential reference, model, options, policy attempt, and Assignment digest to each Run. Provider, model, account, credential reference, route, or options may change only between Runs and require a fresh DSH Agent Session with canonical rehydration. The successor binds the predecessor Receipt and new authorization; provider failover or credential rotation cannot continue an old physical Session under a changed identity.

AI Provider cache behavior is observed optimization, not Work Continuity authority. Runtime records authenticated cached and uncached token usage, cache reads and writes, stable-prefix facts, and invalidation points only where the Provider reports them. Missing telemetry remains `unknown`. A fresh Session may deliberately reproduce an exact stable rehydration prefix, but CodeWiki never weakens semantic binding, retains stale context, or claims a hit to improve cache metrics.

Backend v1 private provider broker owns provider credentials, billing integration, networking, bounded retry/equivalent-endpoint failover, response normalization, and request IDs. Semantic target calls this CodeWiki/DSH trust boundary AI Gateway and calls external model supplier/local inference service AI Provider. Its trusted host may compose exact pinned DSH provider, authorization, and credential Plugins; CodeWiki does not duplicate provider wire or OAuth protocols already supplied by qualified Plugins. DSH inside a Run receives one opaque, expiring, Run- and route-scoped host-local capability rather than provider credentials or unrestricted egress. Unsandboxed qualification may use credential-free TCP loopback; a network-isolated outer Run Sandbox reaches the broker only through one explicitly mounted absolute Unix-domain socket, preserving network namespace denial. Private Provider Broker Protocol `3.0.0` binds the exact Run, account-bearing route, model-request count, input/output token ceilings, broker implementation, and trusted-host configuration into one capability. Each broker call returns authenticated evidence binding that authorization, exact request and response digests, selected provider, account and model, transport-attempt count, normalized usage, provider request ID where available, cancellation or typed failure, and receipt identity. Runtime records validated Receipt in Execution Ledger while trusted AI Gateway storage may retain it independently. AI Gateway and DSH provider Plugins are not CodeWiki Plugins and receive no project or Change authority. Authentication, quota, and budget failures cannot be misclassified as capability problems; Project Server alone interprets typed outcomes and decides whether to rehydrate, select an authorized compatible route, escalate through an authorized transition, request user authority, or stop.

Personal model credentials remain in trusted provider storage, an admitted credential Provider, or existing delegated-product tooling according to the selected route. Configuration and Runs carry account or credential references, never token bytes. Provider Plugins own API-key, PKCE, device-code, callback, refresh, and native-auth mechanics they actually support; Project Server owns account-to-route authorization and cannot widen scopes or routes. Unsupported refresh, revocation, ambient credential, deployment-isolation, or provider combinations fail closed.

Credentials never enter project files, prompts, DSH Agent Sessions, Check sandboxes, Workbenches, collaboration messages, broker receipts, or unrestricted child environments. A local owner-only file is not a same-UID model boundary and qualifies only when every Run sandbox excludes it; multi-user deployment requires a stronger keychain, KMS, or secret-manager Provider. External Agent Client credentials remain entirely external. Channel credentials remain Project Server-side. CodeWiki App, Console, other Clients, and channels receive redacted account, route, authorization-flow, and Receipt metadata only.

Unavailable, unauthenticated, stale, contradictory, or malformed provider state cannot imply acceptance or weaken policy. Provider and channel content remains untrusted until bounded validation succeeds. Replay remains the mandatory deterministic CI route. Deterministic host-local provider fixtures qualify official DSH OpenAI, Anthropic, DeepSeek, and custom OpenAI-compatible API-key wire paths, exact bearer/header behavior, account drift rejection, redaction, budget admission, credential rotation, Broker Host loss, and owner-only local custody without mandatory paid calls. Rotation replaces the owner-custodied value and later calls use only the new secret. Broker Host loss produces no authenticated provider receipt and therefore fails the Run closed; it cannot fabricate output or silently fall back to direct provider networking. Live-provider qualification is opt-in. OAuth remains unsupported while refresh serialization, entitlement filtering, process-loss recovery, and issuer revocation are unqualified.

Backend Support Matrix `1.0.0` publishes the exact production provider boundary: API-key OpenAI, Anthropic, DeepSeek, and operator-defined OpenAI-compatible routes on an isolated single-user Linux x64 deployment. OAuth, ambient environment credentials, secret-bearing provider headers, undeclared families, and multi-user local-file custody are explicitly unsupported rather than best-effort.
