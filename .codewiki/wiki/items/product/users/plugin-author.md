# Plugin Author

Plugin Authors implement CodeWiki Plugins through language-neutral Plugin Protocol and first-party SDKs. Mandatory local Git remains Product infrastructure behind the Project Store port and Git adapter; it is neither a Plugin capability nor a pure-Kernel dependency. Standard Plugin capabilities cover bounded source observation, remote observation/publication, external workspace preparation, verification observation, integration preparation, and Delivery; ongoing third-party connections remain external and bounded namespaced extensions may add mechanics. A remote, shareable, or long-lived Preview is such a protected Plugin effect behind the Preview capability contract; local Worker or Check Preview does not grant provider authority. Apps, CLI, MCP, channels, and services use Kernel API/Client SDK. Check authors use Check SDK. DSH provider/runtime extensions remain DSH Plugins. Obsolete internal provider categories preserved in Git history are not current extension points.

Plugin Manifest binds implementation/dependencies, protocol range, config schema, permissions, isolation, capabilities, and qualification Evidence. Project files may select admitted manifest/config but cannot install code or widen authority. Every invocation is an immutable capability-scoped Request and Receipt. A Plugin receives no canonical Git-ref writer, broad Project Server credential, Result, AuthZ, Change acceptance/completion, or new lifecycle authority. A DSH Plugin's internal composition framework is not a CodeWiki compatibility promise.

Success means any provider can implement the same contract without a core branch or duplicated Stage, scheduler, queue, store, graph, policy engine, credential authority, Result boundary, or guarded effect. SDK language/runtime grants no trust; conformance, admission, exact receipts, and Project Server authorization plus validated receipts do.
