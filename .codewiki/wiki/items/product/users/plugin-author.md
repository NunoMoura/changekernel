# Plugin Author

Plugin Authors implement CodeWiki Plugins through language-neutral Plugin Protocol and first-party SDKs. Mandatory local Git remains Kernel infrastructure. Standard Plugin capabilities cover bounded source observation, remote observation/publication, external workspace preparation, verification observation, integration preparation, and Delivery; ongoing third-party connections remain external and bounded namespaced extensions may add mechanics. Apps, CLI, MCP, channels, and services use Kernel API/Client SDK. Check authors use Check SDK. DSH provider/runtime extensions remain DSH Plugins. Backend-v1 Domain and Infrastructure Provider identities are accepted only by explicit compatibility readers; they are not extension categories.

Plugin Manifest binds implementation/dependencies, protocol range, config schema, permissions, isolation, capabilities, and qualification Evidence. Project files may select admitted manifest/config but cannot install code or widen authority. Every invocation is immutable capability-scoped Request and Receipt. A Plugin receives no canonical Git-ref writer, broad Project Server credential, Result, AuthZ, Change acceptance/completion, or new lifecycle authority. DSH Plugin may use Cordis only inside its separate admitted plane.

Success means any provider can implement same contract without core branch or duplicated Stage, scheduler, queue, store, graph, policy engine, credential authority, Result boundary, or guarded effect. SDK language/runtime grants no trust; conformance, admission, exact receipts, and Project Server enforcement do.
