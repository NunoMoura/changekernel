# Work Unit Execution

Project Server grants one exact Work Unit Claim, selects an eligible Implementation Worker from current Worker Offers and policy, creates and verifies one isolated Workbench, mounts an authorized Project Context Snapshot, snapshots optional Implementation Pack Skills, and persists one Assignment and Run Request binding their digests. The exact `implementation:<work-unit-id>` DSH Agent Session may continue across up to eight bounded Runs while the Assignment lineage, Runtime Build, and custody remain compatible. The first Request creates that Session; retries resume its exact raw log. Each Work Unit Candidate `1.0.0` has exactly one final producing Run and binds all prior receipt identities without copying their bytes. The Worker mutates only its Workbench and cannot grant Claims, schedule canonical descendants, share mutable Workbenches, write canonical state, create authoritative Results, or perform effects.

Every Work Unit Candidate is judged by the same resolved stage-wide Implementation Check Pack policy. Project Server resolves one content-addressed Implementation Stage Policy `1.0.0`, then freezes one Work Unit-specific Gate Evaluation Package `1.0.0` containing the exact Candidate subject and resolved Check Pack snapshot and binding the Work Unit, Assignment, result tree, accepted Knowledge targets, acceptance requirements, repository base, WorkState, Evidence, configuration, routes, declared selections, and execution identities. The package replaces the former Implementation-only package shape; Planning and workers cannot select a bespoke Pack. Independent unit Gates and their isolated Model Checks may run concurrently.

A failed Gate returns atomic feedback to the same Work Unit continuity. A passing Gate qualifies only that exact Candidate. Project Server verifies current Change, Work Graph, dependency, Assignment, Workbench, custody, Candidate tree, changed paths, and Gate identities before creating Private Integration Receipt `1.0.0`. Expected-head compare-and-swap appends that receipt to Change Trace and deterministically reduces Private Change Integration Lineage `1.0.0`; Git stores and anchors exact private commits and trees. `gate_failed`, `gate_passed`, `integration_pending`, `integrated`, `stale`, and `conflicted` remain distinct. Claim loss, malformed output, base or dependency drift, changed custody or bytes, and conflict cannot claim integrated output or alter protected state.

The Change does not enter Review after one unit passes. Project Server advances only after every required Work Unit has a current passing Gate and exact integration receipt, dependency closure and accepted Effect, unchanged-Knowledge, and requirement coverage hold, and Implementation Aggregate `1.0.0` freezes the exact private Git and Change Trace lineage for Review.
