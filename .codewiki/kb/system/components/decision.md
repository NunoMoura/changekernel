# Decision

Decision evaluates one authenticated exact Change revision. The Stage Producer is the sole Candidate producer and directly submits its irreducible disposition and rationale for the exact revision; it does not repeat that revision's Knowledge Effects. Project Server materializes the complete Candidate by binding the submission to the exact revision, producer Run and receipt, WorkState, accepted active Changes, and observed base. Model Checks judge this admitted Candidate and never author or mutate it.

A Decision Candidate states desired meaning, rationale, alternatives, constraints, risks, explicit relationships to accepted active Changes, and either one exact reducible Knowledge transition or explicit unchanged-Knowledge references. An exact transition is an atomic set of `set` or `retire` Knowledge Effects targeting stable semantic subject or facet IDs and binding an expected prior digest or explicit expected absence. Each `set` carries one complete post-state artifact and may create or replace; `retire` requires existing state. Current bytes come from the bound Knowledge State and are never repeated in producer output; exact new semantic content appears once. Human-readable intent summaries and acceptance requirements explain outcome and proof without substituting for, or copying, the executable transition.

Project Context Snapshot queries return bounded current content with stable IDs, facet IDs, content digests, and short context handles. A harness authoring a Change revision may use those handles; Project Server expands them before immutable revision identity. During Decision, the producer references that exact revision without re-emitting its transition. At Candidate checkpoint, Project Server derives machine-owned identity and digests, resolves targets, validates compare-and-swap preconditions, and deterministically compiles the complete transition. It freezes the compiler identity, application-plan digest, projected Knowledge State and projection digests, and exact current-to-projected view into the Candidate and Gate Evaluation Package. Failure to resolve or compile stops Candidate admission before Checks consume tokens. Clients render current state, projected desired state, and diff from these artifacts rather than model-authored repetition.

Decision requires no unresolved semantic contradiction with accepted active Changes. Project Server derives this complete set from canonical WorkState. Accepted Effect Index Protocol `1.0.0` records every accepted nonterminal Change revision as compact Effect-target, invariant-digest, explicit-relationship, and unknown-semantics facts without repeating revision prose. Complete coverage classifies every active Change as `index_only` or `expanded`; Project Server expands full revisions only for shared Effect targets, shared invariants, explicit relationships, or unknown semantics. Duplicate, superseding, dependent, coordinated, and contradictory relationships remain distinct; technical overlap and resource contention are not automatically semantic failure. Decision accepted-active-Changes binding `2.0.0` commits the complete index, coverage proof, relevant expansions, accepted Work Graph, and exact head. The editable default Decision Check Pack includes an `active_change_compatibility` Model Check over those expansions and proof. Incomplete or uncertain coverage stops evaluation rather than silently passing. Planning owns technical dependencies and ordering; Project Server owns live resources; Integration and Review own actual byte and aggregate conflicts.

Decision owns Candidate and attempt semantics under `src/loops/decision/**`. A Change-scoped producer DSH Agent Session may span several bounded Runs. Project Server supplies refreshable immutable Project Context Snapshots to the producer and freezes a separate immutable Gate Evaluation Package only at Candidate checkpoint. Optional Decision Pack Skills may guide evaluation but cannot select disposition or affect Gate authority. Decision Checks independently run through the shared Checks Gate; every Model Check uses its own fresh, tool-free session. A failed Gate returns each atomic failure and its feedback contract to durable WorkState. A stopped Gate preserves current state and reports operational recovery.

A passed Gate certifies only the exact Decision Candidate and compiled Knowledge transition against its frozen inputs. An authorized actor must separately confirm that unchanged Candidate and Gate digest against the current accepted active Changes, WorkState, and Knowledge State heads. Project Server uses expected-head compare-and-swap so concurrently passed incompatible transitions cannot both inherit stale Results. Confirmed `approve` atomically ratifies the Change, applies its exact Knowledge Effects, commits the resulting Knowledge State, and advances the Change to Change-scoped Planning. Confirmed `reject`, `defer`, or `withdraw` records typed meaning without applying proposed Effects. Any Candidate, compiler, base, or relevant accepted-state change requires fresh affected Results. Discoveries that alter accepted meaning return here rather than being silently absorbed by Planning, Implementation, or Review.
