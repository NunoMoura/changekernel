# Decision

Backend v1 Decision evaluates one authenticated exact Change revision. The Stage Producer is the sole Candidate producer and directly submits its irreducible disposition and rationale for the exact revision; it does not repeat that revision's Knowledge Effects. Project Server materializes the complete Candidate by binding the submission to the exact revision, producer Run and receipt, WorkState, accepted active Changes, and observed base. Model Checks judge this admitted Candidate and never author or mutate it.

Backend v1 Candidate states desired meaning plus one exact reducible Knowledge transition or unchanged-Knowledge refs. Semantic Kernel Change schema `4` instead uses one JSONL dossier under `.codewiki/changes/**` across native Git commits. One stable Change ID survives feedback. Each proposal commit appends complete `change.proposed`, contains optional Wiki Item changes, and owns intent, rationale, outcomes, authority intent, compensation/supersession, and explicit Completion Requirements. Its OID is the version; first-parent/tree identity derives Wiki change. No composite version ref, authored impact union, peer Change snapshot, or Wiki Update exists.

Run Context Bundle queries return bounded current Wiki Item content, stable IDs, Git blob/tree OIDs, and handles. A harness authors bounded proposal payload and optional Item files. Project Server validates object types, expected canonical commit, delta limited to that Change trace plus Wiki Item paths, exact predecessor Trace prefix, resulting Item/reference/provenance/retirement closure, active-Change compatibility, and complete requirements before advancing deterministic managed Change ref by expected-old-OID CAS. Candidate and Gate Evaluation Package bind exact proposal commit, managed-ref tip, canonical commit, resulting Wiki tree, and derived Item diff. Failure stops before Checks. Clients render Git-backed proposal and derived Item diff rather than model-authored replacement instructions.

Decision requires no unresolved semantic contradiction with accepted active Changes. Project Server derives this complete set from canonical WorkState. Backend v1 Accepted Effect Index `1.0.0` records nonterminal Change revisions as compact Effect facts. Target index records exact accepted proposal commit OIDs, changed/targeted Wiki Item IDs, invariants, explicit relationships, requirement digests, and unknown-semantics facts. Complete coverage classifies each active Change `index_only | expanded`; expansion occurs only for shared Items/invariants, explicit relationships, or unknown semantics. Duplicate, superseding, dependent, coordinated, and contradictory relationships remain distinct; technical overlap and resource contention are not automatically semantic failure. Decision accepted-active-Changes binding `2.0.0` commits the complete index, coverage proof, relevant expansions, accepted Work Graph, and exact head. The editable default Decision Check Pack includes an `active_change_compatibility` Model Check over those expansions and proof. Incomplete or uncertain coverage stops evaluation rather than silently passing. Planning owns technical dependencies and ordering; Project Server owns live resources; Integration and Review own actual byte and aggregate conflicts.

Decision owns Candidate and attempt semantics under `src/loops/decision/**`. Backend v1 permits a Change-scoped producer DSH Session to span several bounded Runs. Semantic Kernel target retains Change-scoped Work Continuity while giving every terminal producer Run a fresh physical Session epoch. A target proposal attempt rehydrates exact proposal commit and managed-ref tip, authority, canonical commit, derived Wiki tree and WorkState, active-Change coverage, prior Candidate, failed Results and Gate Report, unresolved Completion Requirements, Run Context Bundle construction inputs, and predecessor Receipt. Same-Session resume is only exact recovery of the same unreceipted Run.

Project Server supplies one immutable Run Context Bundle to each target producer Run and freezes a separate immutable Gate Evaluation Package only at Candidate checkpoint. Optional Decision Pack Skills are Backend v1 behavior and disappear at target cutover; neither Skills nor external producer guidance can select disposition or affect Gate authority. Decision Checks independently run through the shared Checks Gate; every Model Check uses its own fresh, tool-free session. A failed Gate returns each atomic failure and its feedback contract to durable Change Trace and WorkState. A stopped Gate preserves current state and reports operational recovery.

A passed Gate certifies only exact Candidate/proposal commit and frozen Git inputs. Authorized Actor confirms unchanged Candidate/Gate against current active Changes, WorkState, canonical commit, derived Wiki tree, and managed-ref tip. Project Server uses expected-head compare-and-swap so incompatible passed Candidates cannot share stale Results. Backend v1 `approve` applies Knowledge Effects. Target creates one disposition commit with expected canonical first parent and exact managed proposal tip second parent. Acceptance uses validated proposed Wiki and freezes requirements; rejection/defer/withdraw retains first-parent Wiki while preserving proposal ancestry and terminal Trace. Empty requirements complete only with non-empty Wiki diff; empty-diff repair requires non-empty Item-targeted requirements. Any proposal commit, base, authority, active state, ref tip, or relevant tree change requires fresh affected Results.
